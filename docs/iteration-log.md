**第五轮：M4 下游实证——revit-spatial-export 实现 对照 + 新一批 Context 缺口回写（2026-09-19，用户确认后实施）**
- 新工作包第一次跑完"Context → 下游真实现"全程：下游 Agent 按 final-prompt 在真实 Revit 2021 中实现双向插件并实测。逐项核验：PROGRESS 证据文件全部属实（DLL 39,936 字节、.addin 已安装、导出 JSON 899 字节内容逐字段吻合、导回 rvt 6.5MB）、final-prompt 内联与独立文件逐字一致、无占位符泄漏、无一处假 ✅。**第三轮反哺被证明起效**：`input_toolchain`（英尺→毫米钉死）直接催生 UnitConverter 并预防了单位类 bug——"待验证：能否消除'作者觉得像'类验收"得到肯定答案。
- 源码逐行复核发现 4 个 P1 实现 bug，全部位于**未实测的多类别路径**（单墙测试不暴露）：① 柱顶标高把"顶部偏移"当绝对高度且未用顶部标高参数；② 门窗 Z 绝对坐标与标高相对值双重累加；③ 自检"全绿"只对账已采集的 7 类，楼梯/MEP 等清单外构件静默消失且机制上不可发现；④ 墙厚导回未还原、注释说"记录偏差"但未落任何记录（验收通过靠默认模板恰好 200mm 的运气）。
- 这批 bug 暴露 4 个第三轮未覆盖的**新 Context 系统性缺口**，据此第六批反哺（Schema/Prompt/模板/编译器六处）：
  1. **"全部/所有"必须枚举化 + 自检分母**：Schema §3 注记、§8 自检、Interview S2b 追问与禁区、S3 模板【范围口径】行——没有清单和分母，"全绿"只证明清单内无遗漏。
  2. **降级对策必须同遍改写验收锚点**：Planning §6 加硬规则（按类别写明保真度，禁止"对策降级、验收仍写完全一致"并存）——门窗位置不还原与验收"主要几何参数一致"的矛盾即源于此。
  3. **坐标语义约定**：Part B §4b 新增必填行（参照系/单位/绝对 vs 相对，禁止混加）——与"英尺→毫米"同级；柱/门窗两个 bug 同源于参照系未钉死。
  4. **往返逐字段对照**：PROGRESS §4 加"逐字段说明导回是否使用"要求、§5 列缺口提示、§2 加"存在 ⏳ 不得写'已完成'"规则（本例 PROGRESS §2 与 §4 曾自相矛盾）；Compiler 自检新增对应 3 项。
- 遗留：上述 4 个实现 bug 待下游 Agent 在多类别实测轮修复（Context 侧责任已尽，属实现层）；新工作包的下一例用于验证"枚举化追问 + 降级联动验收"是否在采访/规划阶段就生效。

  4. **§4 完成定义升级 Iron Law**："没有新鲜验证证据，不得宣称完成" + 反合理化表 + Red Flags。
