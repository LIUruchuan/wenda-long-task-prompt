# 文档与 ADR 检查表（Documentation & ADR Checklist）

> references/ · 按需加载：产物**会被他人/未来的自己阅读**、或有影响后续的重要决策时启用。
> 用法：编译时勾选"文档/ADR"领域 → 随包交付；与 PROGRESS §3 决策记录配套。

---

## 适用信号

- 项目跨会话/跨人（长任务、交接、协作）
- 存在影响后续方向的技术决策（架构、选型、格式、协议）
- 用户要求"文档化/说明/记录"

## 核心检查项

- [ ] 关键决策有**ADR 式记录**：背景 → 选项 → 选择 → 理由 → 代价（PROGRESS §3 的最小 ADR）
- [ ] 文档描述**当前状态**（timeless），不写成变更流水账（"改了什么"进迭代记录，"现在是什么"进文档）
- [ ] 公共接口/格式/命令有文档（与 api-design-checklist 呼应）
- [ ] 文档与代码/事实一致：漂移即缺陷（wenda 自己的"文件为准"纪律）
- [ ] 读者假设明确：给谁看（下游 Agent / 用户 / 协作者），详略随读者

## 常见陷阱

- 文档写"当时怎么做"而非"现在应该怎么做"
- 决策只存在对话里，换人/换会话即丢（ADR 缺失）
- 文档与实现漂移后没人修（比没有文档更危险）
- 把变更历史写进说明文档（历史进迭代记录）

## 反合理化表

| 借口 | 现实 |
|---|---|
| "决策我当时说过了" | 说过 ≠ 记录过；文件才是跨会话的真相 |
| "写文档浪费时间" | 没有文档时，每次回顾都在重新考古，时间更贵 |
| "代码自解释" | 代码解释"是什么"，不解释"为什么选它、放弃什么" |

## Red Flags（出现即停）

- 重要决策（架构/格式/协议）在 PROGRESS §3 无一行记录
- 文档内容与当前实现明显矛盾且无人修正
- 变更历史混入"当前状态"文档

## 验证方式

- 抽查关键决策：在 PROGRESS §3 能否找到"选项+理由+代价"
- 一致性检查：文档声明的行为/字段/命令，在产物中逐一找到落点（wenda 审查记录的方法）
