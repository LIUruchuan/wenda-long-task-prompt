# 前端工程检查表（Frontend Engineering Checklist）

> references/ · 按需加载：产物是**浏览器/界面**（单 HTML、网页、前端应用、可视化、交互 UI）时启用。
> 用法：编译时勾选"前端工程"领域 → 随包交付；核心红线内联 Part A §3b。

---

## 适用信号

- 任何在浏览器中运行的产物（单 HTML / SPA / 可视化页面）
- 有交互、渲染、动画、异步加载
- 依赖外部资源（CDN、模型文件、字体、图片）

## 核心检查项

- [ ] **运行环境钉死**：在哪验证才算数（如"桌面 Chrome 以 file:// 打开"或"本地服务器 http://localhost"）——file:// 与 http:// 的行为差异必须先定
- [ ] 外部资源有加载失败兜底（CDN 双源/降级提示），不因单一资源失败黑屏
- [ ] 交互反馈闭环：每个用户操作有可见结果（加载中/成功/失败/空态）
- [ ] 状态管理不依赖全局隐式变量；页面刷新/会话中断后状态可恢复或明确丢失
- [ ] 浏览器兼容性按环境声明收缩（不支持的能力有提示，不静默降级）
- [ ] 控制台无错误与警告（生产质量基线）；网络请求状态码符合预期
- [ ] 事件绑定/资源清理防泄漏（重复绑定、卸载后仍触发）

## 常见陷阱

- 用 file:// 验证通过、部署到 http:// 后跨域/资源路径全挂
- 单一 CDN 挂了整个页面黑屏（bim 例的双 CDN 看门狗即此教训）
- 只测成功路径，加载失败/空数据/网络慢无界面反馈
- 交互逻辑与渲染耦合，改一处崩一片

## 反合理化表

| 借口 | 现实 |
|---|---|
| "我本地打开没问题" | 验证环境不等于目标环境，file:// vs http:// 天壤之别 |
| "CDN 一般不会挂" | 挂一次就是黑屏一次；双源成本一行代码 |
| "先不做加载态" | 网络慢时用户以为卡死，是可用性缺陷不是细节 |

## Red Flags（出现即停）

- 验证环境未钉死（"浏览器打开"没说哪种、哪个地址）
- 外部资源无任何失败兜底
- 交互无反馈路径（点了没反应、失败静默）

## 验证方式

- 在**声明的运行环境**实测：完整点一遍主流程 + 各交互项（Part A §3 测试规则落点）
- 模拟失败：断网/改坏资源路径，确认兜底生效
- 控制台与网络面板检查：零错误、状态码符合预期
